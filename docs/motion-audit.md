# 动作引擎审计：流畅度与完成度

> 审计对象：`pixel_billboard_actor`（3D 纸片人）+ `pixel_action_module`（程序化动作）
> + `comic_gesture`（2D 关键帧）+ `comic_performance`（语义解析），配套 4 个动作测试。
> 方法：读代码 + 跑 `tools/probe_motion.gd` 实测 + 统计剧情数据里的动作词表。
> 所有数字都可复现，命令见文末。

---

## 0. 结论先说

| 维度 | 评级 | 一句话依据 |
| --- | --- | --- |
| **位移流畅度**（走位/转身） | **A−** | 速度阻尼插值、距离驱动步频、无滑步；起步加速度尖峰 23.7 m/s² 略硬 |
| **姿态流畅度**（动作本身） | **D** | 多数动作只有 1–2 张定格帧；挥手 0 换图；切换动作无过渡 |
| **动作完成度**（词表覆盖） | **D+** | 220 种叙事意图只落到 11 种姿态；**69.4% 的调用最终是 idle**，其中**一半「本该有动作」** |
| **表情完成度** | **F** | 3D 舞台没有接入表情图集，只用「开心/爱/得意 → 第 3 帧」三档判断 |
| **工程可测性** | **A−** | 4 个动作测试共 85 条断言，动作时间轴是纯函数，可无头跑 |
| **性能控制** | **A** | 单格视口 ≤320px、最多 4 个并发、离屏 0.35s 释放 |

**综合判断**：**「移动得很顺，但表演得很少」**。
骨架（时间轴、插值、性能预算、测试）是合格甚至优秀的；但**画面里的人物绝大部分时间是静止的**。
当前一页 2.4 秒，平均只有 **0.66 次换图** —— 也就是**平均每 3.6 秒人物才动一下**。

## 1. 姿态采样率（实测）

同一动作连续 2.4 秒、每 1/60 秒调用一次 `pose()`，统计换图次数：

| 动作 | 换图次数 | 次/秒 | 用到的图 |
| --- | --- | --- | --- |
| `walk` | 19 | 7.92 | 4 张 |
| `talk` | 11 | 4.58 | 2 张 |
| `phone` / `draw` | 1 | 0.42 | 2 张（0.25s 后就不动了） |
| **`wave`** | **0** | **0** | **1 张** |
| `sit` | 0 | 0 | 1 张（靠 squash 表达） |

参考值：2D 手绘动画 12–24fps；像素游戏常态 8–12fps；**本引擎除走路外都在 0–4.6fps**。

`wave` 是 0 —— 因为 `pose()` 对 wave 只做 `_frame = 3` 的常量赋值，
**「挥手」这个动作在画面上完全不挥手**。这是最容易被玩家察觉的一处。

---

## 2. 每页有效动作密度

把词表分布（见第 4 节）乘以各自换图次数，得到一页 2.4 秒的期望：

```
0.694×0(idle) + 0.24×1(其它) + 0.022×19(walk) ≈ 0.66 次/页  →  0.28 次/秒
```

**平均每 3.6 秒，人物才换一张图。** 观众看到的「动」，其实主要来自：

- 镜头与光照（呼吸灯、光池）
- 纸片人的程序化起伏：idle `bob 0.006m @ 2Hz`、`lean 0°`
- 旁白逐字、气泡、拟声词

也就是说：**动的是画面，不是角色。**

## 3. 位移与过渡

### 3.1 位移：这一块是好的

`_arrive()` 用速度阻尼追目标点：

```gdscript
var desired := offset / dist * minf(2.6, dist * 7.0)
_vel = _vel.lerp(desired, 1.0 - exp(-delta * 10.0))
```

- 与帧率无关（`exp(-delta*k)` 是指数平滑的标准写法）
- 走路相位由**实际位移**推进（`_phase += moved * 1.6`），所以**不会滑步**
- 实测 4 秒走位：单帧最大位移 0.037m、平均加速度 0.67 m/s²

**唯一瑕疵**：起步加速度峰值 23.7 m/s²（≈2.4g）。原因是 `desired` 一开始就给到上限 2.6 m/s，
而阻尼系数 k=10，所以 `a ≈ 2.6×10`。视觉上是「啪一下起步」。短距离走位不明显，长距离会有点弹。

### 3.2 过渡：没有

实测 `walk → sit`：**第 0 帧就换图**，之后 2 秒画面完全静止。

- 没有 alpha 交叉淡入，没有姿态混合
- 没有「收势」动作（坐下直接跳到坐下）
- 程序化的 `lean/drop` 是连续的，能掩盖一部分硬切，但掩盖不了「挥手不动」

## 4. 动作完成度：220 种意图 → 11 种姿态

### 4.1 词表覆盖

剧情数据里出现的 `action` 值有 **220 种**，经 `life_comic_pages.action_for()` 的片段匹配后：

| 落到 | 占比 | 次数 |
| --- | --- | --- | --- |
| **`idle`** | **69.4%** | 485 |
| `draw` | 6.9% | 48 |
| `raise` | 4.3% | 30 |
| `phone` | 4.3% | 30 |
| `offer` | 4.0% | 28 |
| `read` | 3.7% | 26 |
| `sit` | 2.2% | 15 |
| `walk` | 2.2% | 15 |
| `receive` / `drum` / `wave` | 2.8% | 20 |

`action_for()` 只有 10 条片段规则 + idle 兜底。把 idle 的 485 次拆开看：

- **264 次是镜头节拍**（`settle` / `establish` / `choice_pause` / `idle` 本身）—— 落 idle 是对的
- **221 次是「本该有动作却没动」**，占总调用 **31.6%**，占**非节拍调用的 50.8%**

这 221 次里，有 26 次属于**纯规则漏项**（引擎其实支持，只是没写进映射表）：

| 意图 | 次数 | 引擎里其实有 |
| --- | --- | --- |
| `sign` | 13 | `comic_motion.NAMED` 有，`ActionModule` 有 clip |
| `talk` | 8 | `comic_gesture.ACTIVE` 有 |
| `put_down` | 5 | `comic_motion.NAMED` 有 |

**改 3 行映射表就能救回这 26 次**，这是全项目性价比最高的一处修复。

剩下的 195 次是真缺口：

| 意图 | 次数 | 现状 |
| --- | --- | --- |
| `look_at_prop` | 25 | idle（本该「看道具」） |
| `react` | 25 | idle（本该有反应帧） |
| `ask` / `ask_company` / `ask_help` | 10 | idle（本该是「开口」） |
| `negotiate` / `decline` / `set_boundary` | 18 | idle |
| `listen` / `heart_listen` | 5 | idle（本该身体前倾） |
| `embrace` / `cry` / `rest` / `sleep` | 9 | idle |

所以「人基本不动」不是美术不够，而是**有 221 次本该动的调用走了 idle 兜底**。

### 4.2 资源量与用量的落差

| 资源 | 数量 | 3D 舞台实际用到 |
| --- | --- | --- |
| `assets/chars` 分件（头/臂/腿/站/坐/抬/挥/idle） | **727 张** | 0 —— 只用整图 |
| `assets/comic_ensemble` 图集 | 3 张（每角色 4 帧） | **4 帧/角色** |
| `assets/comic_actions` 走/动作图集 | 4 张 | 走路 4 帧 + 少量姿态帧 |
| `assets/comic_expressions` 表情图集 | 3 张 + regions | **基本没用**（只做三档判断） |

`comic_art.portrait(key, pose, expression)` 已经支持表情，但
`pixel_billboard_actor.pose()` 调的是 `Art.portrait(character_key, 0)` —— **没传 expression**。
所以 727 张分件与整套表情图集，在正式流程里是闲置的。

### 4.3 三套动作实现并存

| 实现 | 用在哪 | 状态 |
| --- | --- | --- |
| `comic_gesture`（4 帧 + lean/squash，阈值 0.16/0.62s） | 2D 兜底路径 `comic_world` | 在用 |
| `pixel_action_module`（bob/lean/drop，参数化） | 3D 纸片人 | 在用 |
| `pixel_actor_3d`（411 行，带关节的体素骨架） | **无引用** | 闲置 |

同一套「动作」有 3 份互不相同的实现，且两套在用的时序阈值不一致（0.16/0.62 vs 0.25）。
改一个动作要改两处，测两处 —— 这是维护成本，也是「完成度」里容易被忽略的一项。

## 5. 做得好的地方（不吹不黑）

1. **动作时间轴是纯函数**（`comic_motion` / `comic_gesture` / `ActionModule.sample`），
   不依赖节点，所以能无头断言 —— 4 个测试 85 条断言，改完立刻知道有没有破坏既有行为。
2. **帧率无关**：位移、起伏、相位全部按 `delta` 积分，掉帧不会变速。
3. **不滑步**：走路相位由位移推进，这是很多小体量项目会偷懒的地方。
4. **`reduced_motion` 分支**：对晕动症玩家直接关掉 bob/lean，只保留 drop。
5. **性能预算明确**：单格 ≤320px、并发 4 个、离屏 0.35s 释放；
   互动时用「漫画弹窗」代替昂贵的 3D 动作表演 —— 这是很务实的设计取舍。
6. **语义层有否定处理**：`comic_performance` 明确不让「我没有抓住」触发抓取动作。

## 6. 改进优先级（按性价比）

| 优先级 | 改什么 | 具体做法 | 预期收益 |
| --- | --- | --- | --- |
| **P0** | 补 3 条漏掉映射 | `action_for()` 加 `sign` / `talk` / `put_down` → 对应已存在的姿态 | 直接救回 26 次调用，**改 3 行** |
| **P0** | 把「该动却没动」的意图接上 | 再增补 5–6 条：`look_at_prop→read`、`react→raise`、`ask/listen→talk`、`embrace→offer`、`cry/rest/sleep→sit` | 「应动未动」从 221 次降到 ~120 次，**零美术成本** |
| **P0** | 给 `wave` / `phone` / `draw` 补周期帧 | `pose()` 里对这三个动作按 `int(time*6)%4` 循环，而不是常量帧 | 消除「挥手不动」这类硬伤 |
| **P1** | 动作切换加 0.12–0.18s 过渡 | 换图时对 `sprite.modulate.a` 做一次快速交叉，或对 `_lean/_drop` 先插值到中间值再换图 | 消除硬切，观感提升最明显 |
| **P1** | 接表情 | `pose()` 改成 `Art.portrait(key, frame, expression)`（资源已就绪） | 727 张分件与表情图集开始产生价值 |
| **P2** | 走位起步加 ease-in | `desired` 再乘 `smoothstep(0, 0.15, t_since_start)` | 加速度峰值 23.7 → ~10 m/s² |
| **P2** | 合并两套时序阈值 | 让 `comic_gesture` 复用 `ActionModule` 的相位 | 少一份维护 |
| **P3** | 八方向 | 当前靠 `rotation.y` 转纸片，大角度会「纸片转过去」 | 需要新美术，成本最高 |

## 7. 复现

```bash

godot --headless --path . --script res://tools/probe_motion.gd

# 动作相关回归（4 个，共 85 条断言）
godot --headless --path . --script res://test/comic_motion_smoke.gd
godot --headless --path . --script res://test/comic_gesture_smoke.gd
godot --headless --path . --script res://test/pixel_motion_smoke.gd
godot --headless --path . --script res://test/comic_performance_smoke.gd
```

词表覆盖率的统计口径：遍历 `data/*.json` 里所有 `"action"` 字段，
按 `life_comic_pages.action_for()` 的同一套片段规则归类 —— 与运行时完全一致，不是估算。

# 对话手法：学的是「怎么写台词」，不是剧情结构

> 澄清：这次不学《GAMERS 电玩咖》的误会网结构，只学**它的对话手感**——
> 怎么用短句、抢拍、错位、复读和吐槽，把一段日常写得有来有回。
> 下列所有台词都是本作原创，没有复制原作文本。

## 一、六条手法

| 手法 | 做法 | 本作例子 |
| --- | --- | --- |
| **短句抢拍** | 一句只做一件事，砍掉“我觉得”“其实”“然后” | 「你：今天不想补。」「医生：那也得知道补什么。」 |
| **答非所问** | 用另一个问题的答案，暴露说话人真正在意的事 | 「你：电费单在桌上。」「对方：可以当餐垫。」 |
| **抓词复读** | 抓住对方一个词，反着用回去 | 「你：面子能用橡皮撑？」「同桌：能，先用你的。」 |
| **术语落地** | 把工作/游戏词塞进生活对话，制造错位 | 「同事：它没写 deadline。」「你：它有叶子。」 |
| **内心错位** | 心里想的和嘴上说的相反（在四档镜头里成对写） | 嘴上「这真是同事」，心里「她送的是苹果，收走的是我的清白」 |
| **收尾吐槽** | 最后一句短、狠、把前面的话戳破 | 「你：她信了？」「同事：笑得更懂了。」 |

## 二、节奏

- 一段 **4–7 拍**，每 2–3 拍给一个小反转；
- 问句是节拍器：一段里至少一个「？」，用问句推进而不是用叙述推进；
- 结尾一句尽量 ≤ 10 字（「早说。」「让他抢。」「笑得更懂了。」）。

## 四、写进数据的方式

- 每行一句「名字：台词」，靠 `npc_lines` 解析成对白格；
- 四档镜头里的 `inner` 与 `dialogue` 成对写，制造“表里不一”；
- 所有台词都不写舞台指示，动作交给立绘和面板。

## 五·四、标点停顿与句内加速

逐字延迟（`comic_panel.char_delay`）：

| 字符 | 基础延迟 | 额外停顿 | 读感 |
| --- | --- | --- | --- |
| 普通字 | 0.025s | — | 正常 |
| 逗号 / 顿号 | 0.10s | — | 换气 |
| 句号 / 叹号 / 问号 | 0.22s | — | 落点 |
| 省略号 `…` | 0.10s | **+0.16s** | 迟疑 |
| 破折号 `—` | 0.05s | **+0.28s** | 被打断/拖长 |

**句内加速**：连续出现「！」「？」时，后续字的速度每次乘 0.92，最低到 0.72；
遇到句号复位。所以一段越说越急的台词会自己加速，不用手写标记。

## 五·五、语速与抢话（已实现）

**角色语速表**（`comic_panel.cadence_for`）——同一句话，不同人打出来的速度不同：

| 角色 | 倍率 | 读感 |
| --- | --- | --- |
| 你 / 我 | 0.7 | 快，像抢着说 |
| 同桌 / 同学 | 0.85 | 略快 |
| 老师 / 室友 | 1.0 | 标准 |
| 同事 / 销售 / 对方 | 1.05–1.1 | 略慢 |
| 妈妈 | 1.15 | 稳 |
| 医生 | 1.25 | 慢而清楚 |
| 爸爸 / 班长 | 1.4–1.45 | 慢，像在斟酌 |
| 身边的熟人 / 熟人 | 1.5 | 最慢，像在回忆 |

**情绪叠加**（`cadence_for(speaker, expr)`）：同一角色，生气时更快、哭/累时更慢：

| 情绪 | 倍率 |
| --- | --- |
| rage | 0.70 |
| angry / panic / scared | 0.70–0.75 |
| shock / surprise | 0.80–0.85 |
| happy / smile | 0.90 |
| 默认 | 1.00 |
| sad | 1.30 |
| cry / tired | 1.35 |
| sleep | 1.40 |

**抢话标记**：句尾是「——」或「……」时，正文末尾自动补一个 `▍`，
读起来就是话没说完被打断。例如：

> 你：她可能以为……

显示为：

> 你：她可能以为▍

**切角**：打完后如果句尾确实是 `——` / `……`，对话框右下角会斜切 16px（四角变五角），
缺口旁加一道红斜线——这是“被切断”的视觉，而不只是文本里的 `▍`。
打字过程中不切（`needs_cut(text, done)` 只在 done 为真时成立）。

**光标**：逐字显示时行尾一直带一个 `▍`，打完后才换成切角或消失；
框的高度按“已显示的字”计算，所以字出来时框会自然变高（这部分原本就有）。

回归测试：

```bash
godot --headless --path . --script res://test/dialogue_rhythm_smoke.gd
# PASS: speaker cadence and interruption marker helpers
```

## 五·六、旁白插拍

对白之间不能只剩对白。页面生成时会取该事件 `narrator_asides[tier]` 的一句，
插在**第二句对白之后**（`life_comic_pages.make`），所以一页的节奏是：

> 开场旁白 → 对白 1 → 对白 2 → **旁白一句** → 对白 3 …… → 收尾

旁白按抽象度档位取不同的一句：同一段剧情，抽象度高的玩家看到的是另一种吐槽。

**插几次由事件类型决定**（`aside_count_for`）：

| 事件类型 | 次数 | 理由 |
| --- | --- | --- |
| `text_only`（长文本页） | 0 | 本身旁白已经很多 |
| `misread`（误会喜剧） | 2 | 旁白要多嘴两次 |
| `echo`（回响页） | 1 | 一次点到为止 |
| 对白 ≥6 句 | 2 | 对话密集，需要旁白换气 |
| 其它 | 1 | 默认 |
| 显式 `aside_count` | 0–3 | 数据覆盖 |

**插在哪**：优先看数据里的 `aside_plan`：

```json
"aside_plan": {"count": 2, "after": [3, 9], "tiers": [1, 3]}
```

- `after`：第几句对白之后插（1 起）；
- `tiers`：用哪一档旁白（不写就用 `(tier + k*2) % 4`）。

没有 `aside_plan` 时**挑情绪峰值**：以「！」或「？」结尾的对白优先，
不够再用第 2、5、3、4 句兜底；同一页不会出现两句同款吐槽。

回归测试：

```bash

# PASS: narration asides between dialogue turns
```

## 六、没做的

- 口癖还没有做成数据表（现在靠用词区分：爸爸“我自己来”、妈妈“先……再说”、老师“算/不算”）；
- 逐字显示时框虽然会长高，但没有“气泡边缘跟着字推进”的逐字动画；
- 停顿只有标点级，没有“角色沉默 0.6 秒”这类表演级停顿。

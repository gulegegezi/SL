# 人生条漫：折痕与歪楼

本次交付的是 **剧情内容、分镜稿、数据契约与可验证的规则参考**，保存在 `story` 分支。现有 Godot 主控尚未加载新包；不在剧情分支改动动画渲染和共享主控。

- 完整可读剧本：[story-life-events.md](story-life-events.md)。
- 内容数据：[story_life_comic.json](../data/story_life_comic.json)。
- 作者源稿：[build_story_life_comic.py](../tools/build_story_life_comic.py)。
- 规则参考与抽样工具：[story_life_reference.py](../tools/story_life_reference.py)。

内容量：24 个普通事件、72 个选择、144 个随机后续；每个事件均有四档旁白、内心与主角表达，每个结果均保留事实并有四档表达。另有 6 组突发/照护/失去分镜、6 类终章与覆盖层。不是只换几个形容词，也不让高抽象主角真的获得超能力。

## 从旧稿保留什么，改编什么

已读取 GitHub `origin/story` 的总纲、序章、四条关系线与过场说明及对应数据。保留小城、普通人、具体物件、非标准答案；沿用橡皮、鸡蛋、旧钥匙、灯、照片与面馆作为跨年龄回响。

旧稿的事件常在固定年龄或固定链条出现，新稿改为“年龄窗口 + 当下身份 + 记忆 + 存活角色”共同决定候选池。主角不是每年交一次作业，也不必依次完成升学、买房、结婚、生育。拒绝上台仍会留下幕后经历；不借钱仍有朋友的后续；放下旧爱好也有完整结尾。

同一个事件可以在不同存档的不同年龄触发。例如第一次工作在 16–35 岁的就职状态中出现；老同学来电在 24–75 岁且有同桌记忆时出现；旧爱好在 30–90 岁、确实曾留下爱好记忆时回来。范围不是“到这岁必发生”。同一局默认只发生一次，照片和长椅明确允许多年后再出现。

这里的“随机发展”是 **合理候选中的随机**。选择借出一部分钱后，可能按期还上，也可能需要重谈；不会随机变成你从来没借。承诺和已知支出先发生，外界反应再随机。两个后续目前等权，后续可调权重，但不要把隐形的最佳选项写成必胜按钮。

## 一件事怎样画成漫画

每个普通事件默认先有四格：

1. **环境与关系**：用角色位置、具体物件和动作交代处境，不用一大段抽象旁白替代画面。
2. **物件与对方的话**：例如递来的橡皮、停在空中的笔、没发出的离职信。对方有真实意图和生活压力。
3. **主角如何理解**：同一事实，切换对应档的旁白、内心与回应。脑内格必须标明主观边框。
4. **动作停顿与选择**：停在可以伸手、开口、放下或离开的地方，玩家决定主角怎么做。

选择后再画三格：动作确实做出来 → 随机的外界反馈 → 一个物件或收势上的余味。可以把同场的近似格合并，通常一件事占 5–7 格；高抽象时可多一格想象，但它不会多消耗一年或多抽一次死亡。

例：不写“你和同桌建立了友谊”，先画两块硬度不同的橡皮在纸上留下不同痕迹，再画老师敲黑板，两人同时抬头。结果可以变成“第二天那一半又丢了，同桌写来一张失物启事”。让笑点来自人怎样反应。

## 四档抽象程度

| 抽象值 | 档位 | 旁白与内心 | 主角说话 | 画面边界 |
| --- | --- | --- | --- | --- |
| 0–24 | 贴地写实 | 具体观察，允许犹豫和留白 | 直接说出需要 | 现实动作和物件 |
| 25–49 | 日常吐槽 | 观察式幽默与轻度自嘲 | 把紧张说成一个能承受的小玩笑 | 小字、停顿、表情 |
| 50–74 | 脑内小剧场 | 把当前矛盾理解成舞台、桥或小屋 | 与事件物件对应的比喻 | 明确标注的想象格，不改变现实 |
| 75–100 | 宇宙级脑补 | 把同一矛盾放大为航行、系统或荒诞机构 | 夸张但仍能辨认真实诉求 | 想象可放大，事实字幕不可被覆盖 |

“橡皮”一事的主角可以说“谢谢，你用哪半”，也可以说“我们先通个邮”或“请问收不收错别字”；不论怎么想，同桌都只是递来半块橡皮。NPC 不会突然听见主角的脑补字幕，也不会因为抽象值高就集体说宇宙术语。

选择会改变抽象值。开场格使用当时的档位，结算已承诺的选择变化后，结果格使用新档位；跨阈值可以在同一事件后半段看见语气变化。历史格记录当时档位，不随以后分数重写。

抽象值与精神健康是两个独立变量。高抽象可以是想象力和应对压力的表达习惯；低精神健康也可能说话朴素。不得把某档命名为精神疾病、把无厘头当作患病证明。

出生和低龄事件保留年龄逻辑：未满三岁，成人式句子只作内心字幕，实际可听见的仍是婴幼儿发声。老师不会出现在未入学角色的课堂；伴侣不会在没有关系的存档里凭空出现。

## 人生长度与跳年

不在出生时把死亡年龄写死。每一个实际流逝的游戏年都做独立风险结算；没有事件的年份也结算。较好的身体与心理状态会降低部分背景风险；身体较差或心理负担较大时，休息、支持、就医、边界与日常活动具有叙事和状态意义，但不是保证活到某岁的兑换券。

原型的所有分数、概率、转归权重都是 **虚构玩法平衡参数，不代表现实疾病发生率、诊疗结果或寿命预测**。身体分是主要背景因素；心理状态只做较小修正，降至零也不会自动判死。抽象值不进入死亡、事故或癌症随机流。

风险包括背景健康风险、低概率致命意外与独立的癌症发生流。高健康仍可能遇到后两者；确诊后进入信息、支持、治疗、稳定/缓解/进展的过程，绝不是“抽到癌症＝立即结算”。癌症和事故不是不够乐观、没有选对台词、拒绝别人或没组建家庭的惩罚。

参考规则把年轻人的背景死亡记为其他疾病，不把婴幼儿写成“老死”。真正的死因先确定，再叠加未成年或独处的尾声表达；覆盖层不得改写死因。

普通一局抽取 18–24 次决策预算。短命人生可以更少，预算不是寿命；预算用完而人仍在世时，后面可采用真实记忆与日常蒙太奇继续推年，直到出现真实终章。开发抽样达到 140 岁还活着，只标记未完，不伪造死亡。正式实现可以继续年度抽样。

可跳过 1–6 个平静年份。跳年旁白从已存在记忆取材：“那盆小苗换过两次盆，你也换了一个工位。”不要无依据写“你结婚生子了”。已触发的检查、事故和治疗场景必须先解决状态，不能用一句若干年后跳掉等待选择的病情。

## 突发与敏感场景的写法

- 保留确诊、病情、费用、需要帮助等事实；高抽象不能把诊断变成误会、把死亡说成开玩笑。
- 允许主角用想象喘口气，也允许今天完全不开玩笑。不能拿疼痛、癌症或受伤者本身当包袱。
- 治疗选择围绕信息与支持，不给“积极的人必痊愈”或“贫困者必死亡”的隐性规则。有关治疗的具体决定由剧情中的专业照护说明，不让玩家靠一个搞笑按钮猜医学答案。
- 非致命事故后的长期变化有继续生活的剧情。需要辅助和调整不等于失败结局，不要求角色先证明乐观才获得支持。
- NPC 离世后永久记录其角色身份。后面只出现在明确标示的照片、回忆或想象格里，不能作为现场角色说新的生活对白。

## 角色与回响接入

`actors` 是美术槽位，`cast_bindings` 才指向剧情角色。医生借用 `mate` 图像槽位并不意味着“爸爸复活当医生”；新管理员和社区老师也不等于儿时老师。故事中的角色 ID、年龄与是否在世必须独立保存。

旧存档可把真实出现过的 V01、V12、V31 等转成 `legacy:事件ID` 记忆。新包以记忆禁用重复的出生、同桌初识、第一次离家；对应回响仍可接。没有早期爱好记忆，就不出“旧钥匙证明你曾参加排练”的事件。

`LC15` 必须回到同一位同桌，不能借用一个陌生朋友冒充；`LC19` 需要父母确实在世；没有伴侣就不抽 `LC16`。照片旁没有可在场的朋友时，不强行补一句“身边的人问”。剧情池需要保留其他符合条件的事件或用独处蒙太奇过渡。

旧 `health` 如确为 0–20 量纲，可映射为身体分×5；抽象值要先检查实际量纲，不能一律乘五。心理分是新字段，无旧数据时中性初始化为 65，不伪造患病史。不要直接拿 `lifespan` 的旧确定年龄覆盖新年度模型。

## 实现数据的边界

`story_life_comic.json` 是新的内容包，不是直接向 `EVENTS` 数组塞入新字段就能运行的旧事件。`intent` 和 `visual` 是演出意图，像 `shadow_pair`、`teacher_compare` 需要后续动画层映射；不声称 Godot 已支持这些新动作名。

接入次序建议：导入与字段迁移 → 年龄/身份/记忆/存活候选池 → 已选择意图与随机结果的事务式结算 → 四档视角选择 → 漫画分镜播放 → 跳年和每年的风险结算 → 突发状态 → 终章。为旧模式保留原序章；新模式与旧出生开场只能选其一。

分离事件、结果、死亡、疾病、角色与版式随机流。视角选择与动画重播不得消耗结果流；确定结果 ID 和分镜快照后才画出来。保存当前待选页、已提交结果、随机流状态与历史档位，读档不得重抽已显示结果，也不得再扣一次费用。

Python 参考工具用于验证内容和规则，**不是已经接入 UI 的疾病流程**：抽样中的 `pending_editorial_scene` 表示将来应交给分镜状态机的剧情入口；正式接入应暂停普通抽年，逐个处理诊断与安排。不要直接拿年度抽样器当治疗界面。

## 校验与复现

```powershell
python tools/build_story_life_comic.py
python tools/render_story_life_book.py
python test/story_life_content_test.py
python tools/story_life_reference.py --survey 100
python tools/story_life_reference.py --seed 42 --export docs/story-life-sample.json
```

内容校验检查事件、选择、结果 ID；所有 144 个结果均可抽到；年龄与角色前置条件、旧存档去重、提交只结算一次、读档结果一致、跨档位快照。80 组相同种子的四档对照不改变事实链；400 组健康对照中，较好的健康有更长的平均人生，同时仍抽到了癌症与事故。

本次虚构参数的 400 组配对结果：低健康组平均 76.97 岁，高健康组平均 87.51 岁；高健康组仍出现事故、疾病与背景健康终章。它仅用于确认玩法关联有效，不能解读为现实寿命或疾病统计。
# 对白与旁白补充

运行版已采用 [story_life_dialogue.json](../data/story_life_dialogue.json) 中的新旁白稿：24 个事件各有四档引导、三个选择的回应。人物原话保持独立，不再把内心、旁白和对白混在同格，也不重复播报随机后果。四档主角台词仍来自原剧情包；旁白补充稿作为独立来源，不由旧剧情生成器覆盖。

v3 起每个事件追加两组可选扩写：`roast`（旁白解说吐槽，四条，与四档对应，参考《艾希》《传说之下》《三角符文》的叙述者口吻，直接对玩家说话）与 `npc`（人物对话，三条，来自当场的父母、老师、同桌、医生等）。两组均为新增字段，原 `guide`/`responses` 保持不变；旁白吐槽只说话，不改写画面事实。漫画剧情包同步在生成器 [build_story_life_comic.py](../tools/build_story_life_comic.py) 中为每个事件提供 `narrator_asides`（四条档位对应的旁白吐槽）。

旁白的引导与回应参考 [ICEY 开发者对玩家自主行动的说明](https://blog.playstation.com/?p=193550)，全部台词为原创。涉及疾病、事故与离世时避免戏谑诊断或评价当事人的价值。

Godot 接入与旧页面迁移位于 `animation` 分支的 `scripts/life_comic_pages.gd`，本文档所在的 `story` 分支保留剧情来源。
